## E1. APO framework (algorithm)
- **§18.3.1, Listing 18.1, PDF 600–602 (book 569–572).**
- **Problem:** min f(X), X ∈ Ω = Π[x_k^min, x_k^max] ⊂ R^d (Eq. 18.1).
- **Steps:** random init of x and v in the domain → evaluate → X_best → masses → forces → v, x update → repeat.
- **Mass (Eq. 18.2):** m_i = g(f(X_i)) ∈ (0, 1], with g bounded and monotone decreasing (for minimisation).
- **Force, per coordinate k (Eq. 18.3):**
  - F_ij,k = **+G m_i m_j / |r_ij,k|^p** if f(X_j) < f(X_i) (attract toward better)
  - F_ij,k = **−G m_i m_j / |r_ji,k|^p** if f(X_j) ≥ f(X_i) (repel from worse), for all j ≠ i and i ≠ best
  - r_ij,k = x_j,k − x_i,k; p "typically in [−5, 5]".
- **Total force (Eq. 18.4):** F_i,k = Σ_j F_ij,k for i ≠ best. **The best individual feels no force and does not move.**
- **Motion (Eqs. 18.5–18.6):**
  - v_i,k(t+1) = w·v_i,k(t) + **α**·F_i,k / m_i, with **α ~ U(0, 1)** and inertia weight 0 < w < 1
  - x_i,k(t+1) = x_i,k(t) + v_i,k(t+1)
  - Positions are clamped to [x^min, x^max] and velocities to [v^min, v^max].
- **Termination:** maximum iterations, or no change in best for some iterations.
- **Properties:** it is all-to-all (global) and computes forces **per coordinate, independently**. That makes it rotationally variant, as Ch. 19 points out (PDF 630–631).

## E2. Three force laws: APO1 / APO2 / APO3
- **§18.3.2, PDF 603–606 (book 572–575), Figs. 18.3–18.5 (force magnitude against distance).**
- **APO1, "negative exponential" (Eq. 18.7, p = 1):**
  - F = ±r·G m_i m_j / r², i.e. magnitude G m_i m_j / |r|, with **G = 1**.
  - Best individual's mass = **K > 1** (value not given).
  - Total force clamped to **F_i,k ∈ [F_min, F_max], F_min = −F_max**; F_max is "an experiential value" (not given).
  - Drawbacks the text names: poor local search and effectively local reach. SA local search was added in [282].
- **APO2, "unimodal" (Eqs. 18.8–18.10):**
  - F = sgn(r)·G(r)·m_i m_j / r², with **G(r) = g|r|^h for r ≤ 1 and g|r|^q for r > 1, h > 2, 0 < q < 2**.
  - Used: **h = 5, q = 1.** g per function: **Tablet 2.0e4, Quadric 3.0e4, Rosenbrock 5.0e3, Griewank 5.0e5, Rastrigin 500, Schaffer f7 1.0e5.**
  - The force goes to 0 as r → 0 (fine local search) and decays like 1/r for r > 1.
- **APO3, "linear" (Eq. 18.11, p = −1):**
  - F = ±G m_i m_j r_ij,k, so the force grows with distance (spring-like, global), with **G = 10**.
  - The text says G "has little effect" on APO3 and that APO3 has the fewest parameters.

## E3. Benchmark experiment: APO1 vs APO2 vs APO3 on six functions, d = 50 (Table 18.2, Figs. 18.6–18.8)
- **§18.3.2, PDF 606–609 (book 575–578).**
- **Setup:**
  - **d = 50, N = 50 particles, 2,500 iterations, 30 runs** with different seeds.
  - Mass is **Eq. 18.12: m_i = exp[(f(x_best) − f(x_i)) / (f(x_worst) − f(x_best))]**.
  - **w = 0.9 − 0.5·t/MAXITER** (linear from 0.9 to 0.4).
  - **v^min = lower bound of the domain, v^max = upper bound.**
  - Values **< 10⁻¹²** are counted as 0.
- **Functions (Table 18.1):**

  | Function | Formula | Range |
  | --- | --- | --- |
  | Tablet | 10⁶x₁² + Σ_{i=2..d} x_i² | [−100, 100]^d |
  | Quadric | Σ_i (Σ_{j≤i} x_j)² | [−100, 100]^d |
  | Rosenbrock | Σ 100(x_{i+1} − x_i²)² + (x_i − 1)² | [−50, 50]^d; optimum at (1, …, 1) |
  | Griewank | (1/4000)Σx_i² − Πcos(x_i/√i) + 1 | [−600, 600]^d |
  | Rastrigin | Σ(x_i² − 10 cos 2πx_i + 10) | [−5.12, 5.12]^d |
  | Schaffer f7 | Σ(x_i² + x_{i+1}²)^.25 [sin²(50(x_i² + x_{i+1}²)^.1) + 1] | [−100, 100]^d |

  All have minimum 0 at the origin except Rosenbrock. The printed Quadric has Σ_{j=2}^{i}, which is likely a typo for j = 1.
- **Results to reproduce (Table 18.2; Min / Mean / STD):**

  | Function | APO1 (G = 1) | APO2 (g as above) | APO3 (G = 10) |
  | --- | --- | --- | --- |
  | Tablet | 1.17 / 5.13 / 6.46e−1 | 0 / 0 / 0 | 0 / 0 / 0 |
  | Quadric | 1.29e1 / 1.98e1 / 9.22e−1 | 0 (53.3%) / 1.65e4 / 6.84e3 | 0 / 0 / 0 |
  | Rosenbrock | 9.52e1 / 1.63e2 / 1.80e1 | 4.90e1 / 2.50e7 / 9.16e6 | 4.90e1 / 4.90e1 / 0 |
  | Griewank | 1.92e−1 / 2.20e−1 / 3.30e−3 | 0 (40%) / 1.53e1 / 3.70 | 0 / 0 / 0 |

  | Schaffer f7 | 5.75 / 1.56e1 / 1.00 | 0 (40%) / 1.07 / 3.17e−1 | 0 / 0 / 0 |

  - The percentages are the share of runs reaching 0.
  - Qualitative claims: APO3 is best and fastest. APO2 is slow early but reaches the optimum given time. APO3 gets stuck at 49 on Rosenbrock (= d − 1, a local optimum). APO2 is unstable on Rosenbrock (one or two terrible runs).
  - Figs. 18.6–18.8 show mean best fitness against iterations at 20 sample points.
- **Caveat for a porter:** APO3 reaching exactly 0 on 50-D Rastrigin and Griewank in every run is a striking claim. It is very likely helped by the **origin-centred optimum**: the attraction is linear and per-coordinate, and the velocity bounds equal the domain bounds. Ch. 19 (PDF 632) cites the "origin-seeking bias" of PSO and shifts its optima to (100, 100) for this reason. **A faithful port should rerun with the optimum shifted** and report both results.
- **BPP conversion:**
  - Not a physical simulation. Port it as a **headless Lua batch script** in BPP, or in plain Lua outside BPP, with no Bullet bodies. It serves as a correctness test of the APO code and an RNG/seed stress test: α ~ U(0, 1) per particle per dimension per iteration gives 50 × 50 × 2,500 ≈ 6.25 M draws per run.
  - Effort: easy (about 150 lines of Lua). Performance: 2,500 × 50² × 50 ≈ 3×10⁸ force-component operations per run, which is slow in plain Lua 5.1 (minutes per run, × 30 runs × 18 cells). Use fewer runs or C/Python for the full table.
  - Value for the BPP project is low except as groundwork for E8 (swarm robotic search).

## E4. Mass-function comparison: seven mass functions
- **§18.3.3, PDF 609–612 (book 579–581), Fig. 18.9.**
- d₁ = f(X_best) − f(X_i) ∈ (−∞, 0] (Eq. 18.15); d₂ = d₁ / (f_worst − f_best) ∈ [−1, 0] (Eq. 18.16).
- **Convex:** m = 1 + d₂³, 1 + d₂⁵, 1 + d₂⁷ (Eqs. 18.17–18.19). **Linear:** m = 1 + d₂ (18.20). **Concave:** m = (π/2 + arctan d₂)/(π/2), m = tanh(d₂) + 1, m = e^{d₂} (18.21–18.23).
- **Result (qualitative only, numbers are in ref [286]):** convex gives better exploration but slower convergence. Concave converges faster but can get trapped. Overall concave is best, and **e^{d₂} (= Eq. 18.12) is best**.
- **BPP notes:** batch only. It can be checked with the E3 harness by swapping the mass function. Effort: easy. Low priority.

## E5. Convergence analysis: Theorem 18.1 (closed form, checkable)
- **§18.4.1, PDF 613–615 (book 582–584).**
- The analysis uses the linear law (APO3), one dimension, X_best fixed, and sets N_i = {j: f_j < f_i} and M_i = {j: f_j ≥ f_i}.
- Recurrence (Eq. 18.33): X(t+1) − (1 + w − GNM_i)X(t) + w X(t−1) = FG_i, with GNM_i = Σ_{N_i} α_j G m_j − Σ_{M_i} α_j G m_j.
- Expectation: φ_i = E[GNM_i] = ½ G (Σ_{N_i} m_j − Σ_{M_i} m_j) (Eq. 18.35), since E[α] = ½.
- **Theorem 18.1:** for w ≥ 0 and G > 0, {E[X_i(t)]} converges (the text says "to X_best") **iff 0 ≤ w < 1 and 0 < φ_i < 2(1 + w)**.
- **Typo:** the characteristic equation is printed as λ² − (1 + w **+** φ)λ + w = 0 (Eq. 18.37), but Eq. 18.34 has (1 + w − φ). The minus sign is the correct one and gives the stated stability triangle.
- **Checkable by simulation:** fix X_best and the other particles' positions and masses, iterate one particle in 1D for many seeds, and compare divergence against the predicted boundary G_crit = 4(1 + w)/(Σ_{N_i} m_j − Σ_{M_i} m_j). Effort: easy (pure Lua).

## E6. Guidelines for G: particle subsets A, BD, BC (Theorem 18.2)
- **§18.4.2, PDF 615–616 (book 584–585).**
- **Convergence condition (Eq. 18.38):** 0 ≤ w < 1 and 0 < G(Σ_{N_i} m_j − Σ_{M_i} m_j) < 4(1 + w).
- **Subsets:**
  - A: Σ_N m − Σ_M m ≤ 0 (divergent; these are the best particles, Def. 18.1)
  - BD: positive sum but G ≥ the bound (divergent, Def. 18.3)
  - BC: positive sum and G below the bound (convergent, Def. 18.4)
- **Theorem 18.2:** A is non-empty (the best particles always "diverge", i.e. explore).
- **Claims:** a small G makes almost all particles convergent and limits global search. A large G hurts local search. An adaptive G is suggested, with no algorithm given.
- **BPP notes:** theory only. Log the subset sizes in the E3 harness. Effort: easy. Low priority.

## E7. Extended APO (EAPO), vector model (VM-APO), Local APO (LAPO): algorithms without data
- **EAPO, §18.5.1, PDF 616–618 (book 585–587), Listing 18.2:**
  - Adds a personal best P_i (Eq. 18.39). Mass uses f(P_i) (Eq. 18.40).
  - Force toward or away from the other particles' personal bests: F = ±G m_i m_j (p_j,k − x_i,k) (Eq. 18.41).
  - **The best particle now moves too.** The text claims PSO is a special case of EAPO, and that EAPO converges faster and keeps more diversity than APO and PSO. No numbers are given (ref [281]).
- **VM-APO, §18.5.2, PDF 618–619:**
  - Direction is the sign vector r_ij,k ∈ {−1, 0, 1} (Eq. 18.46). Magnitude is G m_i m_j ‖X_j − X_i‖ (Euclidean) (Eq. 18.47).
  - v = w v + α Σ F/m (Eq. 18.48). Steps 1–5 are given. The text argues for diversity (Eqs. 18.50–18.51). No data.
- **LAPO, §18.5.3, PDF 620:** ring and ring-derived neighbourhood topologies. G strongly affects performance. No data (ref [161]).
- **BPP notes:** EAPO and LAPO could be added to the E3 harness. LAPO is the only variant with a local-neighbourhood flavour that maps onto range-limited robots. Effort: easy each. Low priority.

## E8. Applications mentioned only: multi-objective optimisation [258], swarm robotic search [284]
- **§18.1, PDF 598.** No details in this chapter.
- **BPP notes:** "swarm robotic search" with APO is the only bridge to a physical port. Read ref [284] before designing it. Applied literally to drones, Ch. 18 APO is unsuitable:
  1. The swarm **collapses** onto the best individual: the linear law attracts everyone to the best, so there is no separation term and drones would collide.
  2. The best agent is frozen in place.
  3. Every agent needs every other agent's fitness (global communication).
  4. The forces are per-axis, so the behaviour depends on the world-frame orientation.

  Ch. 19's formation-based APO fixes all four and is the version to fly.

## Contradictions with and additions to the existing plan
1. **"APO from altitude (Ch. 18–19)":** Ch. 18 has **no physical or altitude content**. It is a 50-D numerical optimiser with stochastic per-coordinate forces, a frozen best particle, all-to-all fitness sharing and collapse to a point. It should **not** be the basis of the drone port. Use the **Ch. 19 APO**: split-Newtonian formation plus a pairwise fitness force apoF, deterministic, rotation-invariant, local (1.5D). It is a few lines added to the existing triangle-formation code. "From altitude" (drones sensing a ground scalar field from a fixed height) is the plan's own framing and is not in either chapter. It is still a sensible way to make Ch. 19 physical.
2. The Ch. 18 port is best done as a **headless Lua batch benchmark**. It mainly gives (a) a check of the reported Table 18.2 (with an origin-shift control) and (b) heavy RNG use, which makes the appendix's random() issue relevant. BPP's math.random is that generator.
3. The convergence theorem (E5) is a cheap closed-form check, if wanted.
