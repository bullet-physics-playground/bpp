## E1. Swarm-engineering methodology (theory; no simulation)
- **§17.1–17.2, PDF 560–566 (book 529–535).**
- Swarm interaction equation: df_i/dx_j ≠ 0 for i ≠ j. Emergence equations: dP/df ≠ 0 and ∂f_i/∂P = 0 (the global property P is not used by any controller).
- Step 1: write the global state as G = g(x₁…x_Np) (Eq. 17.1–17.2) over the measurables the agents can sense. Step 2: choose the dx_i/dt so that dG/dt = ∇g · dx/dt (Eq. 17.3) moves G toward G_f. The text requires g to be "well-defined and continuous" (a unique final state, plus ε–δ continuity). It also defines "null swarm transformations" (rotation, translation, renumbering), "infeasible regions" and a "Model Independence Conjecture" (footnote 2, PDF 566).
- **Results to reproduce:** none. This is a framework.
- **BPP notes:** nothing to port. The useful habit is to log a scalar "global property" (energy, Eq. 17.7) each tick, so that a port can show it decreasing monotonically. That needs a generic per-tick metric logger, which the probes already roughly provide.

## E2. Hexagon "energy" global property and the derived local rule (theory, checkable)
- **§17.3.1, PDF 567–570 (book 536–539).**
- **Sensing:** each agent knows only the range r_ij (and bearing) to neighbours within sensor range r_s. The theory is 2D, "or airborne swarms limited to a particular altitude".
- **Force law (Eq. 17.5):** F(r) = −G₁ if r < D and r ≤ r_s; +G₂ if D < r ≤ r_s; 0 otherwise. This is a constant-magnitude bang-bang law, "similar to the split Newtonian force law (Eq. 3.3) with p = 0". The net vector is Eq. 17.6, the sum over neighbours of the unit vector times F.
- **Energy (Eq. 17.7):** E = Σ_{i≠j} F(|x_i − x_j|)(D − r_ij), described as potential energy. It is non-negative and smallest for the perfect hexagon. The smooth surrogate is Eq. 17.8: F = lim_{k→∞} G₁ + (G₂ − G₁)(arctan[k(r − D)]/π + ½). dE/dt is Eq. 17.9, and the text argues that E is non-increasing if too-close pairs separate and too-far pairs approach.
- **Local minima:** the lattice can stall in a stable but imperfect state. It must be "shaken" (perturbed), which the text compares to simulated annealing (§17.3.3, PDF 572).
- **Results to reproduce:** E falls quickly and then plateaus above the global minimum (see E4).
- **BPP notes:** compute E per tick in Lua (O(N²), cheap). Ambiguity: as written, Eq. 17.7 is negative for too-close pairs, because F < 0 and (D − r) > 0, and positive for too-far pairs, because F > 0 and (D − r) < 0. So E is ≤ 0 term by term, which contradicts "the energy is non-negative". A port should use |F|·|D − r|, the "distance error" form of §17.3.2, and state that choice. Effort: easy.

## E3. Lowest-energy configuration is the single large hexagon (Theorem 17.1)
- **§17.3.2, PDF 571–572 (book 540–541).**
- **Force for building hexagons (Eq. 17.10):** −300 G if r < D; +G if D < r ≤ r_s; 0 otherwise. A **repulsion:attraction ratio of 300:1** makes it "energetically impossible" for pairs to stay closer than D except transiently. Then E_excess = Σ F_attr (D − r_ij) (Eq. 17.12) counts only the stretched pairs.
- **Theorem 17.1:** the macroscopic state that minimises energy is the single large hexagon. The proof is a hand-waving symmetry argument.
- **Results to reproduce:** the final converged configurations in E5/E6 are one big hexagon (Figs. 17.5, 17.8).
- **BPP notes:** as a check, compute E_excess for a perfect hexagon of N = 61 (5 per side) against other compact 61-agent lattice shapes (rhombus, triangle and so on). This is a static Lua script. ★ The 3D analogue has no unique answer: FCC and HCP stacks, and cuboctahedral against other cluster shapes, are near-degenerate. Whether the "energy" argument picks a unique 3D shape is an open question worth one static calculation. Effort: easy.

## E4. Basic AP behaviour: random → semi-ordered lattice, energy plateau (Figs. 17.2, 17.3)
- **§17.4.1, PDF 572–574 (book 541–543).**
- **Agents:** points in a 2D plane with range-and-bearing sensors. "Move, stop on a dime, and turn in place; **inertia is not modeled**." They are purely reactive with no memory (Fig. 17.1 data path: sensors → processor → actuators).
- **Law:** Eq. 17.5/17.10 (constant-magnitude split law, 300:1). N, D, r_s and step size are **not given**. Fig. 17.2 shows about 50–60 agents, probably the same 61 that form the final hexagon.
- **Results to reproduce:** Fig. 17.2 shows a random cloud becoming a "semiordered" lattice with defects, quickly. Fig. 17.3 shows energy falling from about 18.2 to about 14.35 and levelling off, still above the absolute minimum. Its x-axis runs 0–7 with no units.
- **BPP notes:** 2D particle replica with first-order kinematics (velocity = clamp(F), no momentum). The existing particle scripts include velocity/friction, so add a "no inertia" mode (friction = 1, step = Fmax·dt). This is the same groundwork that Ch. 4 Perfect Formation and Ch. 13 friction need. Effort: easy. On drones, a constant-magnitude ±G switch at r = D is the worst case for the Ch. 13 jitter problem (a hard switch needs instant reversal) and will be worse than Newtonian. Run it only on particles, or smooth it with Eq. 17.8 at a finite k (the arctan form is a free smoothing knob).

## E5. Control Method 1: synchronised hexagonal "drift" (Figs. 17.4–17.6)
- **§17.4.2, PDF 575–577 (book 544–546).**
- **Mechanism:** every agent synchronises (decentralised synchronisation is assumed possible, ref [95]). The whole group translates along the six edge directions of a hexagonal course, clockwise. Each turn "shocks" the lattice. Outer agents that have no neighbours behind them get "dragged" (Fig. 17.4), gain energy, and shift along the edges until the outline becomes a perfect hexagon.
- **Parameters:** none given (drift speed, leg length and number of cycles are not stated). Fig. 17.5 shows a lattice of about 61 agents (5 per side) drifting around a small reference hexagon outline. It takes "several cycles if necessary".
- **Results to reproduce:**
  - Fig. 17.6: energy (log scale, about 15.335 down to 15.319) **steps down** over about 30,000 time steps as defects are removed, with momentary noise, and then stays at a floor.
  - The final perfect hexagon "does not support further shifts" (`moving.hexagon.avi`).
  - Drawbacks the text names: it needs synchrony and space, and the group cannot deploy until it is done. There is no detection of "I am a hexagon".
- **BPP notes:**
  - On particles: add a global drift velocity v_d(t) that cycles through the six 60° directions, summed with the AP force under first-order kinematics. Effort: easy–medium. The leg length and speed must be tuned; one natural choice is legs of a few D at a fraction of Fmax.
  - On drones: this is a real flyable manoeuvre, because the AP waypoints plus a common drift equal a moving goal. The existing goal-following code is almost this (a goal that moves around a hexagon). ★ The 3D version drifts along the edges of a polyhedral course (for example, the 12 directions of an FCC neighbour shell) to anneal a 3D cluster.
  - Ambiguity: how a "turn" happens. The porter can switch direction instantly or blend; the text implies imperfect synchrony is what creates the drag.

## E6. Control Method 2: asynchronous "closing" perturbation by edge agents (Figs. 17.7, 17.8)
- **§17.4.3, PDF 578–580 (book 547–549).**
- **Mechanism:** an agent with **fewer than three neighbours** (edge or corner agents only) is randomly triggered to make a small attenuated move **toward** the group. Moving toward the group raises energy more than moving away, but the move is kept small enough to cause sliding and not a rearrangement. The local energy-reducing response then slides a row of outer agents into new positions (Fig. 17.7). No synchrony and no group motion are needed, and the group can be static.
- **Parameters:** not given. The jump size, trigger probability, and the radius that defines a "neighbour" for the < 3 count must all be chosen.
- **Results to reproduce:** Fig. 17.8 shows a lattice far from hexagonal becoming a good hexagon over six snapshots, with energy "inching down". "In all simulated runs, the system will settle into the hexagonal state eventually"; footnote 4 says it was run **more than 10,000 times** (`stationary.hexagon.avi`).
- **BPP notes:**
  - 2D particles: add a per-agent stochastic kick (probability p per tick, magnitude δ toward the local centroid) gated on neighbour count < 3. Metrics: E(t), time to perfect hexagon, and success rate over many seeds. This needs **batch runs with seeds** (see the appendix note on math.random). Effort: easy–medium.
  - This is a direct competitor to the Ch. 4 Perfect Formation approach. Compare both on the same N.
  - ★ 3D: gate on neighbour count < k₃ (for example < 6 for a surface atom in FCC) and kick inward. This is a cheap 3D annealer. On drones the kick is a waypoint offset, and motor lag will smooth it, which may help.
  - The "random triggering" uses the RNG heavily per tick, which is a seeding concern (appendix).

## E7. Lossless flocking conditions (theory, model-independent claim)
- **§17.5.1, PDF 580–583 (book 549–552).**
- **Definitions:** groups A and B are detached if every cross pair is farther apart than r_s. x_AB is the closest cross-pair vector, and x̄_A, x̄_B are the group centroids. Losslessness requires |x_AB| ≤ r_s always, and if detached then d|x_AB|/dt < 0. With unit vectors x̂_{A→B} and x̂_{A→AB} (Eqs. 17.13, 17.14) and φ = the angle between them, the conditions are Eqs. 17.15–17.16: the agent's motion direction must lie within π/2 − φ of both.
- **Claim:** "lossless swarms can be developed if and only if individuals have access to global information about relative position." Local pairwise information is said to be insufficient. Note that the quark model in E9 is purely local and still claims losslessness. The text reconciles the two only loosely: the farthest-agent weighting acts as a proxy.
- **BPP notes:** no simulation by itself. Use it as a metric: log connected components of the r_s graph per tick and count "lost agents". Effort: easy (a graph component count in Lua).

## E8. Directional (informed-agent) flocking limit and obstacle limit (theory, checkable)
- **§17.5.2–17.5.3, PDF 583–585 (book 552–554).**
- **Hijacking:** the swarm centroid is not used by the controller (Eq. 17.17–17.18), so it can be "hijacked" by a biased agent. This matches the single "rogue"/"informed" agent with a directional bias (refs [28, 115, 229]) and Hettiarachchi & Spears' obstacle work (Ch. 14).
- **The informed agent adds v_b to its computed velocity v_c (Eq. 17.19).** The coherence condition reduces to **Eq. 17.24:** (x̂_{A→B} − x̂_{A→AB}) · v_c ≤ (x̂_{A→AB} − x̂_{A→B}) · v_b. "Too great an added movement, and the swarm will lose the agent." With obstacle avoidance push v_a it becomes **Eq. 17.25:** … ≤ (x̂_{A→AB} − x̂_{A→B}) · (v_b + v_a).
- **Results to reproduce:** no numbers. A port can produce them: sweep |v_b|/v_max and find the threshold above which the informed agent detaches.
- **BPP notes:**
  - This is directly relevant to the existing **goal force** on the drone formations, which is the same structure as an informed bias. It predicts a maximum goal-force-to-formation-force ratio before the swarm splits.
  - Batch sweep on particles first. Effort: easy–medium.
  - Ambiguity: as printed, Eq. 17.24 has the same vector difference on both sides with opposite signs. Re-derive it before trusting it.

## E9. Quark model: lossless coalescence, informed chasing, squeezing through an aperture (Figs. 17.9–17.11)
- **§17.5.4, PDF 586–590 (book 555–559).** This is the main simulation of the chapter.
- **General law (Eq. 17.26):** f_j = Σ_i (1 − δ_ij)(a(r_ij) − b(r_ij)) r̂_ij. Here a is increasing with a vertical asymptote at r = r_s, b is decreasing with an asymptote at r = 0, giving an "infinite potential well with curved walls" between 0 and r_s.
- **Implemented law (Eq. 17.27):** **f_j = Σ_{i within r_s} cot(π r_ij / r_s) · r̂_ij.**
  - cot > 0 for r < r_s/2 (repulsion) and cot < 0 for r > r_s/2 (attraction). The attraction tends to −∞ as r → r_s, so the **farthest visible neighbours dominate**. The implied equilibrium spacing is r_s/2.
  - **Only the direction is used:** u_j = f_j/|f_j|, and every agent moves at **top speed** at all times.
  - Sign convention: r̂_ij points from i to j, so positive values push j away from i.
- **Parameters:** **sensor range r_s = 90 units**; agents randomly dispersed in a **400 × 400 unbounded arena**. Top speed, N and step size are not given; Fig. 17.9 suggests about 150–200 agents. The informed agent's bias and speed are not given; it simply "moves toward the right".
- **Experiments and results to reproduce:**
  1. **Uninformed coalescence (Fig. 17.9, `quark.coalescing.avi`):** dense "swarming centres" form and merge into one symmetric disk-shaped swarm **81% of the time**. Failures come only from singletons that see nobody at t = 0. "No agents get lost along the way."
  2. **One informed agent moving right from the start (Fig. 17.10, `quark.chasing.avi`):** the swarm coalesces while following, connected for a while by a few intermediate agents. It eventually overtakes and absorbs the informed agent. It is lossless.
  3. **Obstacle (Fig. 17.11, `quark.obstacle.avi`):** two "walls" made of closely packed **deactivated agents** form a V/funnel with a hole "much smaller than the swarm's size". The swarm follows the informed agent through it, temporarily loses the informed agent while squeezing, then recaptures it and resumes the disk shape.
- **BPP conversion:**
  - **2D particle replica:** constant-speed direction-only motion. Cap cot near r → r_s and r → 0 (for example, clamp the argument to [ε, π − ε]); the porter must choose ε, because the asymptotes give infinite terms. The walls are static agents (they exert the same cot force), not Bullet colliders. That detail matters: the walls attract at mid range. Metrics: fraction of runs ending as one component (target 81% for random init in 400², r_s = 90, and N chosen to match the figure density), lost-agent count, and passage success. This needs batch seeds. Effort: easy.
  - **3D particles:** the law is dimension-free, so use a 400³ volume. The single-cluster rate will differ (lower density); report it.
  - **Drones (★ the strong demo):** quadcopters at constant cruise speed squeezing through a **window in a wall**, smaller than the swarm, following one informed drone that flies to a goal. The deactivated-agent walls become a wall of "beacon" virtual agents plus real Bullet geometry for collisions. Constant top speed with direction-only commands will make PX4-style drones overshoot and collide at the 0-asymptote. Map u_j·v_max to a velocity command, or to a waypoint at u_j·v_max·Δt, and keep a hard minimum separation. This needs velocity-command groundwork (it is not a position-waypoint law). Effort: medium (particles) to hard (drones through an aperture, collisions, downwash in the squeeze).
  - The existing plan lists "quark model (Ch. 17)". This entry confirms it and adds the specific obstacle test and the 81% statistic.

## Contradictions with and additions to the existing plan
1. **Quark model (Ch. 17)** is confirmed. Add the three tests (coalescence 81% single group, informed chase, aperture squeeze with walls of deactivated agents), r_s = 90 and a 400 × 400 arena. The law is cot(π r/r_s), direction-only at max speed: a different motion model from AP's F → v. On drones it needs velocity commands.
2. **New and not in the plan: perfect-hexagon annealing (Methods 1 and 2).** This is an alternative route to "Perfect Formation" (Ch. 4). Method 2, the asynchronous edge kick, is cheap and generalises to 3D. It belongs next to the Ch. 4 work and the Ch. 13 friction work, which share a "no inertia / first-order" particle mode.
3. **Force law:** Kazadi uses split Newtonian with **p = 0** (constant magnitude) and **300:1 repulsion:attraction**. On drones this is a hard switch and will jitter even more than the Newtonian law (Ch. 13 reasoning). Use particles only, or the arctan smoothing of Eq. 17.8 with a finite k.
4. **Informed-agent bias limit (Eq. 17.24)** gives a theoretical reason for a maximum goal-force share before the swarm splits. This is worth one batch sweep on the existing goal-seeking formations.
5. **Batch/seed groundwork** is needed: the 81% figure and ">10,000 runs" are statistical. See ch20-appendix.md on math.random.
