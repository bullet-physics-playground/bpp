## Common machinery

- Same AP loop as Ch. 2: friction `v←(1−FR)v`, then `Δv = Δt F/m`, then `Δx = Δt v`, with all particles computing forces before any moves.
- Movement is done with `fd sqrt(Δx² + Δy²)` along a heading set from (Δx, Δy). There is no explicit velocity cap in the text.
- **Initialisation for all formation models (Listing 3.6):** `setxy (random-normal 0 20.0) (random-normal 0 20.0)`. That is a Gaussian cloud with σ = 20 patches about the origin, mass 1 and zero velocity, so it is a central dispersion point (MAV container drop, mother vehicle).
- **Checks** shown in every model: the COM must not move, and linear and angular momentum must stay ≈ 0 (Fig. 3.10; the NetLogo y-scale is −1..10). A **Clear** button resets plots after the system is "opened" by kill, birth, goal or disable.

### 3.1 Boids flocking (biomimetic contrast), `flock.nlogo` (Sec. 3.1, Figs. 3.1–3.6, Listings 3.1–3.4, PDF 86–95)

**Agents:** up to 100 boids (`Number_of_Boids`, default 100) moving at **constant speed `fd 1` per tick**. Random positions and random headings at start. Six colours by heading sextant; a histogram bins headings into 0–59°, 60–119°, …, 300–359°.

**Algorithm (Listing 3.1):** find neighbours within `Vision`. If the nearest is closer than `Minimum_Separation`, apply **separation** only. Otherwise apply **alignment** then **cohesion**.
- **Separation:** turn away from the nearest neighbour's *heading*, by at most `Max_Separation_Turn` (`subtract-headings` gives the minimal signed difference).
- **Alignment:** `newh = atan2(Σ sin θ_j, Σ cos θ_j)` over neighbour headings (Eq. 3.2). Turn toward it by at most `Max_Alignment_Turn`. If the sum is 0, keep the current heading.
- **Cohesion:** the same circular mean, but over the *bearings* to neighbours (`b = atan Δx Δy`, NetLogo heading convention). Turn by at most `Max_Cohesion_Turn`.

**Defaults (Fig. 3.1):**

| Slider | Default |
|---|---|
| Vision | 10.0 patches |
| Minimum_Separation | 3.00 patches |
| Max_Alignment_Turn | 5.00° |
| Max_Cohesion_Turn | 3.00° |
| Max_Separation_Turn | 1.50° |

**Results to reproduce:**

| Case | Settings | Outcome |
|---|---|---|
| Default | as above | Common heading emerges; a flock "up and to the left" at **546 steps** (Fig. 3.2) |
| Min separation 0 | Minimum_Separation = 0 | Collapse into a **long linear formation** by **1,309 steps** (Fig. 3.3) |
| Alignment only | Align turn 40, others 0, MinSep 0 | Aligned in **78 steps** (Fig. 3.4 left) |
| Cohesion only | Cohesion turn 40, others 0 | **Small clouds within 42 steps**; boids overlap and never align; histogram in flux (Fig. 3.4 right) |
| Separation only | Separation turn 40, others 0, MinSep 3 | Pairwise avoidance turns only; no cohesion or alignment |

**Worked numeric check (Fig. 3.6):** for the angles {150°, 0°, 0°}, the arithmetic mean is 50°, but the unit-vector mean is atan2(0.5, 1.1339746) ≈ **23.794°**, a discrepancy of 26.206°. For {0°, 45°, 90°} both give 45°. The arithmetic mean of 10° and 350° gives 180° instead of 0°.

**Point made:** boids have no ground truth, are not rigid enough for sensor meshes, and need the **neighbours' headings**, which are hard to sense. AP needs only range and bearing.

**BPP notes:**
- 2D particle replica first: kinematic constant speed with a turn-rate limit. Effort: easy.
- Needs **heading-limited kinematics** (a unicycle model). This model is also groundwork for the Ch. 13 fixed-wing work: constant speed plus a max turn rate is exactly the fixed-wing constraint.
- ★ 3D: boids on **fixed-wing dumbbells or quadcopters** at constant airspeed. Circular means generalise to a 3D mean of unit velocity vectors.
- It serves as the **biomimetic baseline** against which the AP formations' rigidity can be measured: for example, the spread of nearest-neighbour distances versus a triangle lattice.
- The plan says "flocking"; Ch. 3 says the AP alternative to flocking is in **Ch. 17** (summary, PDF 123). Note that Chap. 7 (kinetic theory) is the AP method that uses neighbour *velocities*.
- Decide whether to simulate heading sensing (via compass plus communication, per the "Virtual Heading Sensor" [252]) or give headings for free.

### 3.2 Hooke's-law triangular lattice, `formation_hooke.nlogo` (Sec. 3.2.1, Figs. 3.7–3.12, Listings 3.5–3.8, PDF 96–103)

**Force (Listing 3.7):** if `r < 1.5D`, `F = k(r − D)`, and `if F > FMAX then F = FMAX`. Note that **only the positive (attractive) side is capped in the code**; the repulsive side is not capped. It is summed along the unit vector. Out of range the force is 0. Mass 1.

**Defaults (Fig. 3.7):**

| Slider | Default |
|---|---|
| Number_of_Particles | 50 |
| Spring_Constant k | 0.50 |
| Force_Maximum | 1.0 |
| Friction | 0.50 |
| Time_Step | 0.50 |
| Desired_Separation D | 30 |

**Sensor range rationale (Fig. 3.8):** in a triangular lattice the nearest neighbours are at D and the next at √3 D ≈ 1.73D, so 1.5D sees only the first shell. **Claim to reproduce:** with range 2.5D the cloud **cannot expand into a lattice** ("less is more").

**Results:**
- **Good lattice:** a good, globally imperfect triangular lattice by **200 time steps** (Fig. 3.9). Defects are like crystal defects (bismuth, Fig. 3.11).
- **Conservation:** the COM is static and momenta ≈ 0 (Fig. 3.10).
- **Parameter sensitivity:** **Fmax = 3** leaves the cloud unable to expand, so there is no lattice (Fig. 3.12 left). **Fmax = 5** gives a permanently unstable formation in flux (Fig. 3.12 right). **k = 0.25 with Fmax = 1** also works poorly. Conclusion: Hooke's law is sensitive to its parameters.
- **Kill One** (Listing 3.8) removes a random particle. Holes appear, but the formation stays stable.
- **One is Born** clones a random particle (`hatch`) at an offset of `random-normal 0 (D/2)` in x and y with Δ = 0 and pen down. The formation smoothly absorbs it.
- Momenta jump on kill or birth (the system is opened) and then return to ≈ 0 after Clear.

**BPP notes:**
- 2D particles first, then 3D, then drones. Effort: easy (the existing split-Newtonian code with the force law swapped).
- Needs kill and birth events (scripted or keyboard).
- ★ For drones: "birth" means a drone launched from a ground pad joining the formation. "Kill" means a drone dropping out: land it or remove it.
- The porter must decide whether to keep the book's one-sided cap (it is asymmetric!) or cap |F|.

### 3.3 Split-Newtonian triangular lattice and clustering phase transition, `formation_newton.nlogo` (Sec. 3.2.2, Figs. 3.13–3.16, Listing 3.9, Eq. 3.3–3.4, PDF 103–108)

**Force (Eq. 3.3, Listing 3.9):**
- F = G m_i m_j / r^p, capped at FMAX.
- **Repulsive for 0 < r ≤ D, attractive for D < r ≤ 1.5D, zero beyond.** Code: `if r < view*D`, `view = 1.5`.
- The cap is applied to the magnitude before the sign is chosen.
- The force is discontinuous at D, yet momenta are still conserved.

**Defaults (Fig. 3.13):**

| Slider | Default |
|---|---|
| Number_of_Particles | 50 |
| Gravitational_Constant G | **400** |
| Power p | **2.0** |
| Force_Maximum | **1.0** |
| Friction | **0.50** |
| Time_Step | **1.00** |
| Desired_Separation D | **30** |

The **G Phase Transition** monitor shows 259.81.

**Phase-transition theory (Eq. 3.4):** **G_t ≈ Fmax·D^p / (2√3)**. G > G_t gives clusters (several particles per lattice node); G < G_t gives no clusters.
- Fmax 1, D 30, p 2 gives **G_t = 259.81**.
- Fmax 5 gives **G_t = 1299.04**.
- With the default G = 400, **Fmax 1 clusters and Fmax 5 does not** (Fig. 3.14).
- The mechanism (Fig. 3.15): a particle near a node is pushed back inward by the outer ring, because the split-Newtonian force is not negligible at r ≈ D (unlike Hooke's).

**Experiments:**
- **(a) Default versus Fmax 5:** both give triangular lattices; only Fmax 1 clusters.
- **(b) Hysteresis:** lowering G slowly from 400 shows clusters loosening, then a sudden break-up near G_t. Raising G after a stable formation does *not* create clusters (hysteresis). Clusters reappear only if G is raised *and* new particles are added, or if repulsion is switched off (collapse) and back on with a higher G.
- **(c) Robustness of a clustered lattice (Fig. 3.16):** **50 agents occupy 21 nodes; after removing 25 agents, 19 nodes remain occupied.**
- Formation quality analysis is in [235].

**BPP notes:**
- This is already done (2D/3D, particles and drones). Check the existing scenes against the following:
  - **Default G = 400 > G_t, which means clustering.** With drones, a cluster means two or more drones sharing a node a few patches apart. With the capped repulsion that is a recipe for **jitter and collisions**. ★ For drones, operate at G < G_t (e.g., Fmax 5 with G 400, or G ≈ 0.8·G_t). This may be part of the observed Newtonian jitter, independent of Ch. 13.
  - Add a **G_t monitor** and an automated **G sweep** (batch) measuring nodes-per-particle versus G/G_t. The transition should sit near 1.
  - ★ **3D:** derive or measure the 3D G_t. Eq. 3.4 is derived for a 2D hexagonal ring of 6 neighbours; FCC/HCP has 12 neighbours. Measure it empirically by sweep.
  - ★ **3D range caveat:** in FCC/HCP the **second shell is at √2 D ≈ 1.414D < 1.5D**, so the book's 1.5D view would include second neighbours in 3D. Check that the existing 3D lattice uses a range in (1, 1.41)·D, e.g., 1.3D.
- Units: D = 30 patches; the scale factor to metres is the porter's choice.

### 3.4 Split-Newtonian square lattice (two particle types), `formation_newton.nlogo` with Toggle Formation (Sec. 3.2.3, Figs. 3.17–3.20, Listings 3.10–3.11, Eq. 3.5, PDF 108–113)

**Types:** even `who` are white, odd are yellow (one bit). Unlike types sit at D; like types at √2 D.

**Implementation (Listing 3.11):** do not change D. For **like** pairs, renormalise `r ← r/√2` and use `view = 1.3`. For **unlike** pairs use `view = 1.7`. The default triangular case uses `view = 1.5`.
- Rationale for 1.7: the second unlike shell is at √5 D ≈ 2.236D.
- Rationale for 1.3: the like-shell ratio is 2/√2 = 1.414.
- The text says the behaviour is "not very sensitive" to these view values.

**Phase transition (Eq. 3.5):** **G_t ≈ Fmax·D^p / (2 + 2√2)**. With the defaults that is 900/4.828 ≈ **186.4** (computed here, not printed). Clustering occurs at Fmax 1 but not at Fmax 5 (Fig. 3.18).

**Defects** are larger than in the triangular case, because the initial mix of types matters.

**Defect removal by noise, i.e. annealing (the result to reproduce):**
- Raise **Time_Step above 1.00**: inaccuracy acts as noise.
- **Lower Friction to about 0.1, then raise it** (Fig. 3.19 left, applied to Fig. 3.18 left).
- **Add particles:** 10 extra added to Fig. 3.18 right gives Fig. 3.19 right.
- **Occasionally flip a particle's type** (colour). This removes defects but eventually dissolves clusters ([236] has quality results).
- **Repeatedly hit Toggle Formation** (triangle ↔ square). Each transformation improves quality.

**Scalability:** **500 particles** form good triangular and square lattices using the friction lower-then-raise trick (Fig. 3.20).

**Moral:** noise improves AP formations. Real robots' sensor and actuator noise is beneficial, and the text advises ignoring noise unless the hardware is truly unreliable.

**BPP notes:**
- Square: already done. Add:
  - a **friction-annealing schedule** (time-varying FR), a **type flip** action, and a **triangle↔square toggle** event;
  - a **lattice-quality metric**, e.g., the fraction of particles with the correct number of neighbours at D ± 10% and correct angles; [235]/[236] define metrics, which the porter should look up;
  - **batch scaling to 500 particles** (particle mode only; 500 drones is probably too heavy).
- ★ **3D:** two types with like pairs renormalised by √2 gives **simple cubic as the rock-salt (NaCl) structure**. It is the same code as 2D square. In NaCl the type is the parity of i+j+k, so the body-diagonal neighbour at √3 D is *unlike*. Unlike shells are therefore at D, √3D, √5D; like shells at √2D, 2D, √6D. A like view of 1.3 (after renormalisation) still works, since 2/√2 = 1.414. The **unlike view must drop below √3 ≈ 1.73**. The 2D value 1.7 is borderline; use about 1.5. Verify by test.
- ★ **Drone noise test:** the drones' own tracking error may serve as the annealing noise. Compare lattice quality for particles versus drones.

### 3.5 Honeycomb lattice (Sec. 3.2.4, Figs. 3.21–3.22, PDF 113–115; McLurkin [157]; `honeycomb.nlogo`, `honeycomb.avi`)

**Shows:** the honeycomb gives the **maximum area coverage for N particles at spacing D** of any regular lattice.

**Two types again:** unlike at D, like at **√3 D**, implemented by renormalising **`r ← r/√3`** for like pairs. Each hexagonal cell has 3 + 3 particles.

**Problem:** a particle at a cell centre is trapped in a potential well by its 6 neighbours. If every centre fills, the lattice becomes triangular.

**Fix A (McLurkin [157]):** in a perfect honeycomb each particle's neighbours at D are separated by 120°. A particle that sees neighbours separated by **60°** perturbs itself to escape. Snapshots at steps **5, 10, 100, 1,800** (Fig. 3.22): the start is a small cluster, repulsion expands it, a clear honeycomb exists at 100, and it is much improved by 1,800 with repair.

**Fix B (`honeycomb.nlogo`):** **periodically switch between square and honeycomb**. The square lattice has no centre wells, so trapped particles escape. Details are only in the .nlogo, not in the text.

**Unspecified:** the view (sensor range) values for honeycomb are not given in the text.
- Suggested: unlike view < 2 (the next unlike shell is at 2D), e.g., 1.7.
- Like view < √3 after renormalisation (the next like shell is at 3D, i.e. √3 after renormalisation), e.g., 1.3.
- Also unspecified: the perturbation magnitude, the switching period and the robot count. **Obtain `honeycomb.nlogo`** if possible.

**BPP notes:**
- Medium: needs the angular-neighbour test, a perturbation, and a scheduled lattice switch.
- ★ **The 3D analogue is the diamond lattice:** two FCC sublattices, unlike at D, like at √(8/3) D ≈ 1.633D. The honeycomb's centre-trapping problem reappears as interstitial sites. Its detection test generalises: 4 unlike neighbours at tetrahedral angles of 109.47° versus defects at 60/70.5°. This matches the plan's "honeycomb/diamond".

### 3.6 Moving formation to a goal with obstacles, `formation_goal_obs.nlogo` (Sec. 3.3, Figs. 3.23–3.26, Listings 3.12–3.15, PDF 115–121)

**Breeds:** particles, goals, obstacles.

**Initial layout:** particles start as the Gaussian cloud on the **right** of the pane; the goal (blue) is on the **left**.

**Defaults (Fig. 3.23):** the same as 3.3 (N 50, G 400, p 2, Fmax 1.0, Friction 0.50, Δt 1.00, D 30), plus **Goal_Force 0.25** and **Obstacle_Force 10**. Monitors: Abandon Goal Force = 1, G Phase Transition 259.81, #Disabled and #Obstacles.

**Goal (Listing 3.13):**
- A **constant-magnitude attractive force `goalF`, sensed at any distance** (like a GPS waypoint). It is toggled by **Toggle Goal** and is off at start.
- The goal is modelled as an **extremely heavy particle**, so the COM jumps to the goal when it is enabled. Turning it on opens the system, so momenta deviate; Clear shows them returning to 0.

**Obstacles (Listings 3.14–3.15):**
- Placed by mouse click: a heavy, green disk of drawn **size 2·obstacleF** (diameter).
- **Repulsive force F = obstacleF − r for r ≤ obstacleF**. It is linear and also sets the sensing range. Example: at r = 9 with obstacleF 10, F = 1.
- Goals and obstacles do not interact with each other.
- **The obstacle force must exceed the goal force**, or particles pass through obstacles (or crash, on hardware).

**Disable One:** a robot is made extremely heavy, so it barely moves but still exerts forces (purple). The goal and the disabled particle have identically heavy masses, so the COM goes mid-way.

**Results:**

| Experiment | Outcome |
|---|---|
| Goal force 0.25 | Slow arrival; the lattice settles centred around the goal (Fig. 3.24 left) |
| Goal force 2.00 | Fast arrival; the formation is **compressed** by the goal (Fig. 3.24 right) |
| Disabled robot, goalF 0.25 | Most particles go to the goal, but neighbours of the disabled particle may stay behind |
| Disabled robot, larger goalF | The bond is capped at Fmax = 1, so **goalF must exceed Fmax (≈ > 1) to abandon** (the "Abandon Goal Force" monitor = 1). Several adjacent disabled particles need more, and it is computable from physics (footnote 7) |
| 12 obstacles, obstacle size 10 (narrowly spaced, between the formation and the goal) | The formation slowly **twists and rotates minimally** through; all reached the goal in that run, though not always (Fig. 3.25) |
| Obstacle size 50 | Obstacles form a large virtual wall; the **whole formation rotated en masse around the northern end of the wall** (emergent) (Fig. 3.26) |

**Further claims:**
- Some courses are traversable and some are not (an open problem).
- **AP solves obstacle densities 3× higher than biomimetic methods [93]**, using a **Lennard-Jones** variant (Ch. 14). LJ formations are more fluid-like. File: `formation_lj_goal_obs.nlogo`.
- The obstacle size can be changed live with the slider.

**BPP notes:**
- Already done for particles and drones (goal and obstacles). Check fidelity:
  - constant goal force at any range;
  - goal as a heavy particle (only matters for the COM display);
  - linear obstacle repulsion `obstacleF − r` within radius obstacleF;
  - obstacles placed as a **wall of 12 discs between the cloud and the goal**, for the 10 versus 50 cases.
- Add a **Disable One** event. ★ For drones: a drone that is "stuck" (holds position, or gets a heavy virtual mass) while its neighbours keep feeling it. Measure the goalF threshold for abandonment versus the predicted Fmax.
- Mouse placement becomes scripted obstacle layouts. Random fields are needed for batch density sweeps toward Ch. 14 and 15.
- ★ **3D:** obstacles as spheres or vertical cylinders (trees, pillars). The size-50 "wall rotation" should become a formation flowing over or around a wall, and choosing between "over" and "around" is a new 3D emergent effect to look for.
- ★ Compare split-Newtonian versus LJ obstacle-density success (the 3× claim) via batch runs. That is the bridge to Ch. 14/15.
- Effort: easy for the remaining pieces.

### 3.7 Hardware requirements (Sec. 3.4, PDF 121–123), no experiment

**Requirements:**
- **Goal sensing** by GPS (direction and range to the goal).
- **Obstacle sensing** by acoustic (sonar time-of-flight) or **IR triangulation** rangers. The authors used IR triangulation sensors extensively.
- **Neighbour range and bearing** is the key requirement. Ceiling cameras are centralised (not acceptable), on-board omni cameras are too costly computationally, and **GPS is not accurate enough** (footnote 9).
- **Their solution is RF + acoustic trilateration:**
  - Each robot simultaneously emits an RF pulse (clock start) and an acoustic pulse.
  - Neighbours have **3 acoustic receivers**; three distances give range and bearing.
  - Robots **take turns** emitting.
  - The RF pulse can carry data: **1 bit for the square/honeycomb type**, or packets.
  - Details are in Ch. 10.

**BPP notes:**
- Groundwork item: a **neighbour-sensing model** in place of perfect positions:
  - range/bearing noise;
  - a max range;
  - optional line-of-sight occlusion by obstacles or other robots;
  - a round-robin update rate (staleness);
  - a 1-bit type payload.
- Obstacle sensing becomes **ray casts** (Bullet `rayTest`) with a range limit, instead of known obstacle centres.
- The goal comes from a noisy GPS.
- These turn the "perfect AP at 5 Hz" drone runs into book-faithful ones. Effort: medium. Needed for Ch. 10–12 anyway.

## Contradictions / additions to the existing plan

1. **Clustering versus jitter.** The book's default split-Newtonian parameters (G 400 > G_t 259.81) *deliberately* produce clusters, i.e. several agents per node. If the drone port used these defaults, drones share nodes and fight the capped repulsion, which is a plausible jitter source besides Ch. 13's explanation. Re-run the drone Newtonian scene with G < G_t (or Fmax 5) before concluding that the "friction fix" is needed.
2. **3D sensor range.** The 1.5D view is a 2D triangular-lattice choice. In 3D close packing the second shell is at 1.414D. Verify the existing 3D runs.
3. **Hooke's-law formations** (in the plan) are explicitly fragile: Fmax 3 or 5, or k 0.25, fail. The port should reproduce the failures as well as the success at k 0.5 / Fmax 1. The code caps only the attractive side.
4. **Honeycomb (plan item)** has two concrete methods in the text: √3 renormalisation plus 120°/60° defect repair [157], or square↔honeycomb toggling (`honeycomb.nlogo`). Diamond is the natural 3D analogue; it is not in the book.
5. **Noise/annealing is missing from the plan:** the friction lower-then-raise schedule, Δt > 1, type flipping, formation toggling and particle insertion. Add a lattice-quality metric and a 500-particle scaling run.
6. **Robustness events are missing:** Kill One, One is Born and Disable One (heavy mass), plus the **abandon-goal-force = Fmax threshold** test, which is cheap and gives a clear theory-versus-sim check.
7. **Boids baseline:** the plan's "flocking" should include the Ch. 3 boids model (constant speed, turn caps 5/3/1.5°) as the biomimetic baseline. Per this chapter, AP flocking proper is in Ch. 17, and velocity-based AP is in Ch. 7.
8. **The LJ obstacle claim (3× obstacle density versus biomimetic [93])** belongs with Ch. 14 and is a natural headline result for the existing LJ drone scenes.
9. **The sensing model (trilateration, IR rangers, GPS)** is new groundwork not in the plan.
