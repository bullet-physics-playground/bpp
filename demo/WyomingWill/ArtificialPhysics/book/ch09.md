## E4. Finite-difference stencils (Table 9.2, p. 260 / PDF 291)

- Forward: ∂u/∂x ≈ (u(i+1,j) − u(i,j))/Δx, O(Δx); ∂²u/∂x² ≈ (u(i,j) − 2u(i+1,j) + u(i+2,j))/Δx².
- Backward: mirror images.
- **Central: ∂u/∂x ≈ (u(i+1,j) − u(i−1,j))/(2Δx), O(Δx²); ∂²u/∂x² ≈ (u(i+1,j) − 2u(i,j) + u(i−1,j))/Δx².**
- GDMF in 2D (Eqs. 9.1–9.2): ∇·(ρV) = u ρ_x + ρ u_x + v ρ_y + ρ v_y; GDMF = ∇ of that.
- Fig. 9.5: formations used as sensor grids — square and hexagonal lattices, the hexagonal one with
  **non-uniform spacing** to boost coverage locally (no parameters).

**BPP notes.** Library code for the neighbour-based estimator (see Ch. 8 E3). For irregular swarms use
least-squares plane fit over neighbours; validate against Ch. 8 E5/E6 analytic fields. Easy.

## E5. Forward model: filament/puff plume simulator (§9.3, pp. 260–264 / PDF 291–295; Fig. 9.6)

Based on Farrell et al. [59] (UC Riverside), reimplemented with multithreading and **solid rectangular
obstacles** added (obstacles impenetrable to fluid and robots).
- **Wind (§9.3.1):** random wind vectors at the 4 corners of the rectangular area → linear interpolation
  along the 4 edges (Dirichlet boundary) → interior by "second-order accurate forward Euler in time,
  central difference in space" scheme on a uniform grid. (The PDE being integrated is not stated; Farrell's
  original solves a 2D advection/diffusion of the velocity field. With obstacles the flow goes around them.)
- **Mixing (§9.3.2):** white noise σ added to advective velocity each step; time correlation, bandwidth,
  gain exactly as Farrell [59] (values not given in the book).
- **Puff growth (Eq. 9.3, p. 263):** r_k(t) = (r_o^{2/3} + γ t)^{3/2}, t = puff age in steps, γ =
  volumetric diffusion rate, r_o initial radius (no values given).
- **Density (Eq. 9.4):** ρ(x,y,t) = Σ_{k=1..M} ρ_k, ρ_k = Q/(√(8π³) r_k(t)³) · exp(−S_k(t)²/r_k(t)²);
  Q = chemical per puff, S_k = distance from puff k centre to (x,y). Sphere template flattened to a disk
  in 2D.
- Environment discretised into cells, each storing V and ρ; robots read the cell under their centre.
- Flow regimes used throughout: an even mix of laminar, transitional and turbulent (set via boundary
  conditions); emitter runs 3000 steps before robots deploy (Exps. 2–4).
- Fig. 9.6 demo: 7-robot hex lattice starts lower-right, meandering plume from top-left emitter (triangle),
  arrows = wind; frames T = 283, 1470, 2456 — lattice reaches the emitter by ~T = 2456 with fluxotaxis.

**BPP notes.** This is the main new groundwork for CPT. Implement in Lua: puff list (position, age),
advect by interpolated wind + σ noise, grow radius, sum Gaussians at query points. Wind: start with the
corner-interpolation field with no obstacles (bilinear interior is enough for a first replica); for
obstacles, solve a potential-flow / Laplace problem on a grid (Jacobi iterations, no-penetration on
boxes) — porter must decide, since the book does not give the PDE. Render puffs as translucent spheres or a
shaded ground slice. Parameters (Q, r_o, γ, σ, emission rate, grid spacing, wind magnitudes) must be
chosen; take Farrell et al. 2002 values if available. Medium–hard. ★ 3D is natural: Farrell's puffs are
spheres, so keep the z coordinate, add a vertical wind profile (log/shear layer) and let drones trace at
several altitudes (a 3D lattice gives ∂/∂z too). ★ Underwater version for AUVs (hydrothermal vent, cited
in Ch. 8) uses the same model with current instead of wind.

## E6. Generalized Lennard-Jones formation law (§9.4.1, §9.4.3, pp. 265–268 / PDF 296–299; Fig. 9.7)

- Eq. 9.5: F_formation = ε F(D)^α / r^β − κ F(D)^γ / r^δ (first term attractive, second repulsive), with
  F(D) = (ε D^{δ−β} / κ)^{1/(γ−α)} chosen so that the force is zero at r = D. Typical α < β ≤ γ < δ.
- Fig. 9.7 example: **D = 5, ε = κ = 1, α = 1, β = γ = 2, δ = 3** ⇒ F(D) = D; force mostly repulsive, weak
  attraction for r > 5 ("liquid-like" bonds, good near obstacles/narrow passages).
- **Used in all experiments: F_LJ = D/r² − D^{1.7}/r^{2.7}** (i.e. ε = κ = 1, α = 1, β = 2, γ = 1.7, δ = 2.7;
  F(D) = D), exponents "selected based on the dimensions of our laboratory prototypes". Same law and
  parameters for every swarm size (7–150) and obstacle density.
- Net force → velocity vector (first-order, not F = ma; p. 265), then clipped by mechanical limits.
  No Fmax, no friction, no cut-off radius stated; D = 3 m inter-vehicle spacing in Exp. 2 (E11); other
  D values not stated for the large swarm.

**BPP notes.** Note it differs from the Ch. 3 LJ already in BPP (different form/exponents, no ε/σ
standard LJ). Add as a new force-law option; check the zero at r = D and plot vs Fig. 9.7. Easy. Porter
must choose the interaction cut-off (≈1.5D as in Ch. 3 is a reasonable default) and max speed. Because it
is velocity-commanded and weakly attractive, it should settle on drones like the existing LJ.

## E7. CPT simulator top-level loop and robot model (§9.4.2–9.4.3, Listing 9.1, pp. 266–269 / PDF 297–300)

- Robots: homogeneous disks of fixed radius (value not given); sensors at centre: anemometer (V) and
  chemical sensor reporting ρ only above a threshold (value not given). No sensor/actuator noise.
- Loop per step: `ap_maintain_formation(lattice)` (formation forces → desired velocity); for each agent
  `agent_do_cpt_strategy(agent)` (adds CPT velocity); `move_agents_with_constraints` (keep in arena,
  clamp to mechanical limits, no collisions).
- **Behaviour subsumption:** collision avoidance overrides the CPT output near obstacles or when another
  vehicle is closer than a safe separation radius.
- Every CPT run = casting until plume found, then tracing to a single stationary emitter.

**BPP notes.** Matches the existing BPP AP structure (formation force + goal → waypoint/velocity). New:
an obstacle/robot collision-avoidance override layer and arena bounding. Easy.

## E8. Seven-robot hexagonal-lattice algorithms (§9.4.4, Listings 9.2–9.5, Fig. 9.8, pp. 269–275 / PDF 300–306)

Hexagon of 6 + 1 centre robot; lattice radius D is a dynamic control variable; movement by waypoints
(1 m apart in Exp. 1).
- **Casting (Listing 9.2):** pulsating lattice — expansion factor incremented to a maximum then decremented
  to a minimum, radius = expansion factor × D_o; centre robot moves side-to-side/up-down, reversing
  horizontal or vertical direction when blocked; waypoint = direction unit vector × D_o.
- **Chemotaxis (Listing 9.3):** if in plume, move lattice to the robot position with maximum ρ; else cast.
- **Anemotaxis (Listing 9.4):** if in plume and V detected, average V direction over the 7 robots and move
  one step along −V at maximum speed; else cast.
- **Fluxotaxis v1 (Listing 9.5):** if in plume: if centre robot senses > 50% of total lattice ρ → contract
  to minimal radius (emitter enclosed); else `chem_region`: sense total ρ at **3 lattice radii** (inner,
  middle, outer), compute ρ-weighted centroid at each, r_Cp = (1/Σρ_i) Σ ρ_i (x_i, y_i), N = 7;
  – ρ increases with each radius increase → move to centroid of the 3 centroids;
  – else if outer ρ > inner ρ → move to outer centroid;
  – else if ρ decreases with radius → `flux_ring`; else cast.
  `flux_ring`: flux across each of the 6 outer hexagon edges = average of the two robots' ρ and V, edge
  length × unit depth as area, origin at edge midpoint ((x_A+x_B)/2, (y_A+y_B)/2); classify in-/out-flux
  by flow direction relative to lattice; move to max **influx** if above flux threshold, else to max
  **outflux** if above threshold, else cast. Threshold value not given. Finite-volume discretisation [247].
- Known limitation stated: the 3-radius expansion takes time while the plume evolves (not time-accurate).
- Chemo/anemotaxis lattices expand/contract radius **at random** in Exp. 1 for fairness.

**BPP notes.** 2D particle replica first (7 point masses), then 7 drones at fixed altitude. Needs: dynamic
D, centroid computation, edge-flux computation. All centralised-ish (lattice-level decisions) — implement
as a "lattice controller" script that sets the centre waypoint and D. Medium. ★ 3D: replace hexagon with
a 13-node cuboctahedron or 7-node octahedron+centre and integrate flux over faces (Ch. 8 E2 shell).

## E9. Arbitrary-size swarm algorithms (§9.4.5, Listings 9.6–9.9, Figs. 9.9–9.10, pp. 275–281 / PDF 306–312)

No waypoints; velocity from formation forces + CPT goal vector each step; each robot uses only neighbours.
- **Casting (Listing 9.6):** move along **45° diagonals**; "bounce" reflection at obstacles and arena
  boundary; on reversal **broadcast** the new horizontal/vertical direction (recursive local broadcast to
  keep the swarm synchronised); each robot has its own casting state, stops casting when it finds plume;
  split-off groups cast independently. velocity = direction × time step.
- **Chemotaxis (Listing 9.7):** if neighbours present: find neighbour with highest ρ; ∇ρ := ρ_max − ρ_self
  (direction toward that neighbour); if |∇ρ| > 0, velocity = ∇ρ × time step; else cast.
  (Scalar times what direction is left implicit: interpret as vector toward the max-ρ neighbour scaled by
  the difference — porter decides.)
- **Anemotaxis (Listing 9.8):** if ρ_self > 0 and |V| > 0: velocity = −V × time step; else cast. No sharing,
  no memory; averaging emerges through the lattice.
- **Fluxotaxis v2 (Listing 9.9):** if more than one neighbour: for each neighbour n compute
  flux_n = ρ_n |V_n| cos(atan(v/u) − atan(dy/dx)) (= ρ_n V_n·n̂ with n̂ along the neighbour line, dx,dy =
  separation vector); sign tells influx (toward self) vs outflux; if any influx → unit vector toward the
  neighbour with max influx; else if any outflux → unit vector toward neighbour with max outflux; else
  chemotaxis. If ≤ 1 neighbour → anemotaxis. velocity = F × time step.
  (Use atan2, the printed arctan is quadrant-ambiguous.)
  Claim: the swarm's implicit sum of these per-robot vectors is a first-order approximation of GDMF that
  approaches the second-order GDMF as swarm size grows.
- Emergent behaviour to reproduce (Fig. 9.9, ~20–30 robots, 4 rectangular obstacles, frames T = 87, 939,
  1692, 2123): swarm **splits into two groups around an obstacle and rejoins**, flows "like syrup"
  upstream; after finding the emitter it **surrounds it and keeps enclosing it**.
  Obstacles generate chemical sinks, so flux-following routes around them before collision avoidance fires.

**BPP notes.** Main port target. 2D particles first, then drones at fixed altitude, then ★ full 3D:
neighbour-line flux works unchanged in 3D (n̂ = unit separation vector, flux = ρ_n V_n·n̂), so the
3D generalisation is literally free — good candidate for the "fluxotaxis 3D" plan item. Needs neighbour
messaging of (ρ, V) and a casting broadcast (multi-hop flood). Medium.

## E10. Experiment 1 — 7 robots, unobstructed, vary max expansion factor (§9.5.1, Fig. 9.11, Table 9.3, pp. 281–284 / PDF 312–315)

- World: 930 m² area, no obstacles; mix of laminar/transitional/turbulent flows; plume evolves during
  tracing (no pre-run stated). 3000 steps per run (~1 h). Waypoints 1 m apart.
- Lattice: initial radius 0.5 m, **max expansion factor 15 ⇒ max lattice diameter 7.5 m** (so factor ×
  0.5 m = radius). (Text also defines expansion factor as "the largest separation distance between any
  two vehicles" — inconsistent; porter decide.) 10 expansion factors (Fig. 9.11 x-axis 5–15).
- Runs: **35 plumes × 10 expansion factors × 200 random start locations** per algorithm.
- Metrics (end of run, normalised, 1.0 best): emitter proximity of centre robot; CPT success = emitter
  inside lattice.
- Results (Table 9.3, mean ± sd over plumes and parameters):
  - Anemotaxis: proximity **68.43 ± 0.29 %**, success **6.67 ± 3.62 %**
  - Chemotaxis: **67.45 ± 0.49 %**, **31.84 ± 1.32 %**

- Fig. 9.11 shape: fluxotaxis proximity ≈ 0.88→0.92, flat; anemotaxis proximity rises ≈ 0.66→0.72 and passes

  overshoot upwind → exit plume → cast back → repeat). Success: fluxotaxis ≈ 0.65→0.76; chemotaxis ≈ 0.31→

## E11. Experiment 2 — 7 robots with obstacles, vary start distance (§9.5.2, Fig. 9.12, pp. 284–287 / PDF 315–318)

- Inter-vehicle spacing fixed at **3 m**. Start distance from emitter **0–25 m**, **500 random starts** per trial.
- Obstacle sets: none; one 3×3 m (1% coverage); four 1.5×1.5 m (1%); two 3×3 m (2%); eight 1.5×1.5 m (2%);
  total **150 plume+obstacle configurations**. (1% of 930 m² ≈ 9 m² ✓.)
- Emitter on for **3000 steps before** robots activate; then **7000 steps** of CPT.
- Metric: **stability / containment** = fraction of the 7000 steps the emitter is inside the lattice
  (global observer).
- Results: average containment **fluxotaxis 49.1%, anemotaxis 8.4%, chemotaxis 7.2%**. Chemotaxis starting
  within 3 m: only **14.3%**. Anemotaxis spends > 90% of the mission in upwind/overshoot/cast cycles.
  Fig. 9.12 curves: fluxotaxis ≈ 0.75 at 0 m decaying to ≈ 0.3 at 25 m (noisy); chemotaxis ≈ 0.17→0.02;
  anemotaxis ≈ 0.1→0.02. Fluxotaxis < 100% even when starting enclosed because gusts shed chunks of plume
  that look like temporary sources.
- Observation: lattices avoid obstacles well before active collision avoidance triggers (they follow the
  flow around obstacles).

**BPP notes.** Needs obstacles in the flow model (E5) — the obstacle-induced density build-up (sink) is
what defeats chemotaxis, so a wind field that does not flow around obstacles would not reproduce this.
Medium–hard.

## Relation to the existing plan

- Plan item "fluxotaxis 3D (Ch. 8–9)" is confirmed but the book's experiments are **2D ground robots**;
  a faithful **2D particle replica comes first** (E5 puff model + E9 algorithms + E12/E13 metrics), then
  drones at fixed altitude, then true 3D. The swarm-v2 neighbour-flux rule (E9) generalises to 3D with no
  changes — cheapest route to "fluxotaxis 3D".
- New groundwork not in the plan: (1) puff/filament plume model with wind and obstacles (E5) — the biggest
  item; (2) neighbour data messaging (ρ, V) and flooding broadcast for casting; (3) casting behaviour;
  (4) collision-avoidance subsumption; (5) headless batch runs with CSV metrics (E10–E13 total >40,000 configs).
- New force law: the generalized LJ F = D/r² − D^1.7/r^2.7 (E6), distinct from Ch. 3's LJ.
- Hardware experiment E1 (Maxelbots, ethanol, Figaro TGS 2620) is reproducible in BPP and is small — a good
  early demo of "3 robots beat 1".
- ★ Ideas invited by the chapter: AUV/hydrothermal-vent version (shares Ch. 6 ASV/AUV vehicle work);
  vehicle-induced flow perturbation using the existing drone downwash model; multiple/mobile emitters and
  turbulence mitigation (listed future work, p. 298); sensor noise (excluded in book).
