# Chapter 19 — Artificial Physics for Noisy Nonstationary Environments

- **Author:** William M. Spears (Swarmotics LLC)
- **Book pages:** 591–613. **PDF pages:** 622–644 (PDF 645 is blank; Appendix A starts on PDF 646). Book page = PDF page − 31.
- **Sections:** 19.1 APO and Tracking; 19.2 NetLogo implementation of APO; 19.3 Comparison of APO and PSO (19.3.1 2D, 19.3.2 higher dimensions); 19.4 Summary.
- **NetLogo model:** **`apo.nlogo`**. The 2D/30D comparison code is C-like pseudocode (Listings 19.2, 19.3); the source is not named.
- **Core idea:** a rigid AP lattice is a population that **does not converge prematurely**. It keeps sensing the large-scale structure of the field, so it can (a) cancel noise by **implicit consensus** (the "table carried by many people" analogy, PDF 623) and (b) **track** a moving optimum without any trigger. No randomness is used apart from the initial placement, and the method is **rotationally invariant**.

## The algorithm (shared by all entries)
- **Listing 19.1 (NetLogo, PDF 627) and Listing 19.2 (d-dimensional, PDF 632).** For each pair (p, k) with r < **1.5D**:
  - **Formation force (split Newtonian):** F = G / r^POWER, clipped to F ≤ FMAX. It is attractive if r > D and repulsive if r ≤ D, applied along delta/r.
  - **Fitness force (minimising):** if fitness[p] < fitness[k] (p better), p is **repelled** from k by apoF; if fitness[p] > fitness[k], p is **attracted** to k by apoF. This is constant magnitude along delta/r.
  - On equal fitness, Listing 19.2 adds nothing; Listing 19.1's `ifelse` makes it attractive. To maximise, flip the inequality (footnote 1, PDF 625).
- **Mass = 1 for all particles** (unlike Ch. 18).
- **POWER p = 2. G = 0.9·Fmax·D²/(2√3)**, set automatically from Eq. 3.4 to avoid clustering. **apoF = 0.10**, from Eq. 6.2 (PDF 626).
- Each particle evaluates fitness once per iteration (N calls per iteration, the same as PSO). There is **no memory** of past bests.
- **Metric:** distance from the **centre of mass** Σm_i x_i / Σm_i (Eq. 19.1) to the optimum, not best-ever fitness.
- **Noise:** **uniform on [−Noise/2, +Noise/2]**, added to each fitness evaluation (PDF 626).
- **Lower bound:** at least **d + 1 particles** are needed to search d dimensions. Two particles form a 1-D "leader–follower" line (PDF 629–630).

## E1. apo.nlogo demo: seven particles find the Rastrigin minimum (Figs. 19.1, 19.2)
- **§19.2, PDF 624–626 (book 593–595).**
- **GUI defaults (Fig. 19.1, read from the sliders):** **Number_of_Robots = 7, Force_Maximum = 1.0, Friction = 0.50, Time_Step = 1.00, Desired_Separation = 50, Noise = 0.** At setup the Distance-to-Optimum monitor reads 413.04.
- **World:** the 2D Rastrigin function (Table 18.1) drawn as patch colours (brighter yellow = worse). The optimum (blue circle) is at lower left. The particles start as a **very small cluster at upper right**.
- **Results to reproduce (Fig. 19.2):** the formation self-organises and moves to the optimum along a **smooth, nearly straight** centre-of-mass trail, and distance against time falls smoothly.
- **Derived G:** with D = 50 and Fmax = 1, G = 0.9·2500/3.464 ≈ **649.5**.
- **BPP notes:**
  - **2D particles:** the existing Ch. 3 Newtonian triangle code plus about 10 lines for the fitness force and a scalar field f(x, y). Effort: easy.
  - **Groundwork:** a scalar-field function in Lua, a coloured ground texture or heightmap so the field is visible, and centre-of-mass trail drawing.
  - **Ambiguity:** how apo.nlogo maps patch coordinates to the Rastrigin argument (scale and offset) is not stated. The 2D experiments (E7) put the optimum at (100, 100) in a 900 × 900 world and evaluate the function on raw coordinates. Use that convention.

## E2. Noise robustness: Noise = 600,000 and 5,000,000 (Fig. 19.3)
- **§19.2, PDF 626–627.**
- At 600,000 the optimum is still visible in the noisy landscape. At **5,000,000** the landscape "looks extremely random", yet **seven particles still surround the optimum**. It takes a long time and the trajectory is less straight.
- The noise is large relative to the signal. With raw coordinates in [0, 900]², Rastrigin values are at most about 10⁶, so a single comparison is nearly a coin flip. The formation integrates many comparisons over time. This is the implicit-consensus claim.
- **BPP notes:** the same as E1 plus noise. This is a good demo of **sensor noise**, a general groundwork item (one RNG draw per sample, which is an RNG-quality issue; see the appendix). Effort: easy.

## E4. Zoom experiment: when small-scale structure becomes large relative to D (Fig. 19.4)
- **§19.2, PDF 627–629.**
- Zooming in by 10 or 100 reveals Rastrigin's "waffle board" local minima. **Zoom 10: APO usually succeeds. Zoom 100: the particles get stuck in local optima.** The fix is a D large enough to make small-scale structure irrelevant.
- **BPP notes:** use a scale parameter s on the field, f(x/s) with s = 1, 0.1, 0.01 in the text's sense (zoom = 1/s). Measure the success rate against D/feature-size. Effort: easy. This is a nice batch plot: success against D·zoom.

## E5. Interactive tracking: move the optimum by clicking (Fig. 19.5)
- **§19.2, PDF 629–630.**
- Clicking moves the optimum. The formation immediately turns toward it, with no trigger. Fig. 19.5 shows a centre-of-mass trail with several direction changes; the field display is disabled for that figure.
- **BPP notes:** a key binding or slider for the goal position. The existing BPP goal machinery (G key, `goalSpeed`) already moves a goal. Here the "goal" is the field's optimum, sensed only through pairwise fitness comparisons, not a goal force. Effort: easy. ★ **Strong drone demo:** a drone formation with downward-looking sensors follows a moving ground "hotspot" (fire, spill or plume source) using only pairwise comparisons, with no goal coordinates given to any drone.

## E6. Two particles: leader–follower line; d + 1 minimum
- **§19.2, PDF 629–630.**
- With N = 2 the pair chases along a **straight line** and cannot search 2D. The lower bound is N ≥ d + 1.
- **BPP notes:** trivial to show. In 3D the minimum is 4 (a tetrahedron), which matters for drones. Effort: easy.

## E7. 2D APO vs PSO, stationary noisy functions (Table 19.3, Fig. 19.7)
- **§19.3.1, PDF 631–635 (book 600–604).**
- **PSO (Eqs. 19.2–19.3, Listing 19.3):**
  - Global-best topology (all particles see each other). **ω = 0.729, c₁ = c₂ = 1.49.** r₁, r₂ are U(0, 1) per dimension per particle.
  - **Vmax = 450** (half the search space). PSO particles start uniformly random in **900 × 900**.
- **APO:**
  - Particles start as a **small cluster at a random location** in the 900 × 900 region.
  - **D = 300** for all 2D experiments. There is no Vmax in APO.
  - Fmax and friction are not restated; presumably the NetLogo-style settings, with G set from D as above. **Ambiguous.**
- **World:**
  - Screen coordinates: origin at the upper left, +y down. **The optimum is shifted to (100, 100)**, which avoids PSO's origin-seeking bias. Either algorithm may leave the 900 × 900 region.
  - Functions and noise (Table 19.3): **Ackley noise 100, Griewank 500, Rastrigin 5,000,000, Step 5,000,000.**
  - **Discrepancy:** the Fig. 19.7/19.8 panel titles say **Ackley Noise = 5**, not 100. Ackley in Table 19.3 uses exp(−.002·sqrt(Σx²/d)), not the usual −0.2, because of the coordinate scale. Step = Σ(⌊x_i + 0.5⌋)².
- **Run:** **100,000 iterations, N = 3 and N = 7, 50 runs.** The optimum is static.
- **Results to reproduce (Fig. 19.7; distance of centre of mass from optimum, y-axis 0–700; values are approximate from the plots):**
  - **N = 3:**
    - PSO stalls at about 350 (Ackley) and about 420–480 (Griewank, Rastrigin, Step).
    - APO falls to about 20–40 by roughly 30–40k iterations (Ackley, Rastrigin, Step) and steadily to about 90 by 100k on Griewank.
  - **N = 7:**
    - Both do well. PSO is about 50–110 (Griewank about 110) and APO about 20–50.
    - **PSO is better at the very start**, because uniform init places some particles near the optimum and APO must travel from its cluster.
- **BPP notes:**
  - APO in 2D particles is easy. PSO is not physical (velocity up to 450 per step); implement it as a pure-Lua batch comparator.
  - **Port as a headless batch harness** in Lua: 100k iterations × 50 runs × 2 N × 4 functions × 2 algorithms. That is heavy in Lua 5.1; consider C for the full grid.
  - Effort: medium.

## E8. 2D nonstationary tracking: APO tracks, PSO cannot (Fig. 19.8)
- **§19.3.1, PDF 634–636.**
- **The same as E7, but after 10,000 iterations both coordinates of the optimum increase by 0.01 per iteration** (0.01414 per iteration diagonally). An extra test at **0.001** per iteration gave similar results.
- **Results to reproduce (Fig. 19.8):**
  - **APO:** stays at about 30–50 (N = 3: about 35 on Ackley and Griewank, about 70–90 on Rastrigin and Step) and about 30–45 (N = 7) for the whole 100k run.
  - **PSO, N = 3:** dips to about 280–350 around 20–40k iterations (the optimum passes near the particles) and then climbs past 600 by about 80k.
  - **PSO, N = 7:** climbs roughly linearly from about 50 at 10k to about 700 by about 60k.
  - Claim: "In two dimensions PSO is unable to track even a very slowly changing environment."
- **BPP notes:** as for E7. For the physical port, the drift speed must be expressed in agent units. With D = 300, 0.01414 per iteration is very slow; the 30D case (E11) is faster. Effort: medium (batch).

## E9. Rotated-ellipse test: rotational invariance (Fig. 19.9)
- **§19.3.1, PDF 636–637.**
- A "highly eccentric ellipse" from ref [237]; the eccentricity and coefficients are **not given here**. **N = 7, Noise = 50,000, 30,000 iterations.** Two cases: major axis along x, and rotated 45° counter-clockwise.
- **Results to reproduce:**
  - **APO is identical in both cases**: from about 500 down to about 20 by 20–30k.
  - **PSO**: reaches about 0 immediately when axis-aligned, but **stalls at about 220** when rotated.
- **BPP notes:** the porter must pick the ellipse, for example f = x'² + 1000·y'² in rotated coordinates. Batch, 2D. Effort: easy.
  - ★ In 3D, show rotational invariance by rotating a 3D field arbitrarily: APO drone formations behave the same, and Ch. 18's per-axis APO and PSO do not.
  - A related trap: the existing BPP AP code, if it uses per-axis clamping of force or velocity (for example clamping x, y, z separately to Fmax), is itself rotationally variant. Check that Fmax clamps the vector magnitude.

## E10. 30-D trajectory shape: APO straight, PSO axis-aligned staircase (Fig. 19.10)
- **§19.3.2, PDF 637–638.**
- Noisy stationary Rastrigin in **30 dimensions**, optimum at (100, …, 100), each dimension in [0, 900]. Both start **near the farthest corner** of the hypercube from the optimum.
- **Result:** in a 2D projection the PSO centre of mass follows a jagged staircase of moves parallel to the axes, and APO follows a smooth near-diagonal path. Both reach the optimum.
- **BPP notes:** ★ the physical meaning is that APO gives **flyable** trajectories. A drone demo can fly a formation commanded by APO against PSO-generated waypoints (shown as point particles or ghost markers) over the same field, making the "smooth trajectory" argument visible in 3D. Effort: medium.

## E11. APOH (PSO → APO hybrid) on eight 30-D nonstationary functions, hand-set D (Table 19.4, Fig. 19.11)
- **§19.3.2, PDF 638–641 (book 607–610).**
- **APOH:**
  - **Stage 1:** standard PSO from uniform init for **I = 5,000 iterations**.
  - **Stage 2:** re-initialise all particles as a **small cluster around one randomly chosen particle** of the converged PSO population (the cluster size is not given), then run APO until the end. **D is used only in stage 2.**
  - Footnote 3 suggests alternating APO and PSO continually (future work).
- **Setup:** **d = 30, N = 60** (2d; d + 1 = 31 is the minimum, but 2d "works better", perhaps two particles per axis). **10 runs.** After **10,000 iterations the optimum moves +0.01 per dimension per iteration** (0.05477 per iteration). The runs last about 100,000 iterations (x-axis about 95k).
- **Functions and noise (Table 19.4):** Ackley 5, Distance (sqrt Σx²) 500, Griewank 500, Rosenbrock 5, Rastrigin 500,000, Schaffer f7 5, Schwefel (Σ_i (Σ_{j≤i} x_j)²) 500, Step 500,000.
  - **Discrepancy:** Fig. 19.11's panel titles show **Schwefel Noise = 50**. Fig. 19.13's show **Griewank 50 and Schwefel 50**. The table says 500 for both.
- **D used (Fig. 19.11 titles):** **300** for Ackley, Distance, Griewank, Rastrigin and Step; **30** for Rosenbrock and Schwefel (narrow corridors); **600** for Schaffer (wide circular ridges, Fig. 19.12).
- **Results to reproduce (Fig. 19.11; y-axis to 4,500–5,000):**
  - **PSO** distance grows roughly linearly to about 4,500 by about 95k iterations: it does not track at all, and footnote 4 says the same with zero noise.
  - **APOH** stays near 0 to about 300 on all eight:
    - about 300 on Griewank
    - about 200 at the end on Schaffer, after descending from about 2,000
    - near 0 on the rest
- **BPP notes:** **batch-only** (30-D). It is the strongest scientific result of the chapter but has no physical embodiment. Port as a Lua or C batch harness if reproducing the book is a goal. Effort: medium (the code is easy; run time over 30 dimensions × 60 particles × 100k iterations × 10 runs × 8 functions is large in Lua).

## E12. APOH with cyclic D (30 → 600 via sin): fully automatic (Fig. 19.13)
- **§19.3.2, PDF 641–642.**
- In stage 2, D cycles smoothly between **30 and 600 using sin()**. The **period is not given**, so the porter must choose it.
- **Results to reproduce:** mean centre-of-mass distance over all problems, runs and iterations is **134.91 (sd 223.42)** for cyclic D, against **118.73 (sd 210.72)** for hand-set D, about 13% worse. Fig. 19.13 shows the per-function curves; APOH ≤ about 300 everywhere, and Schaffer ends at about 100–150 after descending from about 2,000.
- **BPP notes:** ★ "breathing" formations (D oscillating) are a physical, visible behaviour and easy on particles and drones. On drones the D cycling rate is limited by how fast the lattice can re-equilibrate (the motor-lag and settle times from the existing findings). Effort: easy (particles) to medium (drones).

## E13. Tracking visualisation (Fig. 19.14)

## BPP conversion summary for Ch. 19 (the physically meaningful part)
- **What to build first:** "APO formation" = the existing split-Newtonian (or Lennard-Jones) lattice + a pairwise fitness force apoF within 1.5D + a scalar field + noise. In 2D particles, reproduce E1–E6 (apo.nlogo) and Table 19.1.
- **Drones (★ what "APO from altitude" should mean):** quadcopters at a fixed altitude each sample a ground scalar field at their (x, y), with additive uniform noise, and exchange fitness with neighbours within 1.5D. Use a triangle formation (N ≥ 3) tracking a moving hotspot (E5, E8).
  - Use the **Lennard-Jones** formation law or Ch. 13 friction, because the split Newtonian law jitters on drones. Check that the extra constant ±apoF term (a hard sign switch on noisy comparisons) does not add jitter; it will flip randomly under heavy noise. Low-pass filtering by motor lag may actually help.
  - **3D:** a full 3D field f(x, y, z), for example a 3D plume concentration (link to Ch. 8–9 fluxotaxis), with a tetrahedral or cubic drone lattice (N ≥ 4).
- **Groundwork:**
  - scalar-field module (analytic functions: Rastrigin, Ackley, Griewank, Step, ellipse, moving Gaussian), plus field rendering (ground texture or coloured point grid)
  - sensor-noise model
  - centre-of-mass trail
  - distance-to-optimum logger
  - headless batch runner with seeds
  - optional PSO comparator (pure Lua)
- **Scale mapping:** the book's units are abstract (D = 50 in NetLogo, 300 in the comparisons). For drones, pick D in metres (for example 2–4 m), scale the field so that its features are about 0.1–10 D (E4 shows the ratio is what matters), and convert "iterations" to AP ticks at 5 Hz.

## Contradictions with and additions to the existing plan
1. **"APO from altitude (Ch. 18–19)":** neither chapter mentions altitude. Ch. 19's APO is 2D (NetLogo) and abstract 30-D. The deployable algorithm is the **Ch. 19 formation APO**, not Ch. 18's (see ch18.md). Ch. 19 states that this needs only "a very simple modification to the code for triangular formations", which BPP already has.
2. **Additions:**
   - the N × D table (Table 19.1) as the primary quantitative target
   - zoom (feature size against D)
   - d + 1 minimum (4 drones in 3D)
   - rotational invariance (check BPP's own clamps)
   - tracking a moving optimum
   - cyclic D ("breathing")
   - the PSO comparison as a batch-only baseline
3. **Discrepancies in the book to note in any port:** Ackley noise 100 (Table 19.3) against 5 (Figs. 19.7–19.8); Schwefel and Griewank noise 500 (Table 19.4) against 50 in the Fig. 19.11/19.13 titles. The ellipse definition, the cyclic-D period, the APOH stage-2 cluster radius and the 2D-comparison Fmax/friction are not given.
4. **RNG:** the PSO side of these experiments uses random() heavily, and the appendix was born from this work (see ch20-appendix.md).
